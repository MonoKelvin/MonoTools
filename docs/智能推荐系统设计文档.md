## 1. 设计概述

### 1.1 背景与目标

MonoTools 现有智能排序基于**硬编码规则引擎**（`APP_CATEGORIES` + `RECOMMENDATION_MAP`），存在以下局限：

- **静态规则**：推荐逻辑硬编码，无法根据用户实际使用习惯动态调整
- **上下文感知弱**：仅依赖前台应用类别，未利用窗口标题、浏览器标签、编辑器文件等 richer 信号
- **无学习能力**：无法从用户反馈中优化推荐质量
- **冷启动依赖人工配置**：新应用类别需手动添加关键字

**设计目标**：

1. 引入机器学习推荐算法，提升推荐精准度
2. 实时提取桌面应用上下文（浏览器标签、编辑器窗口等）
3. 设计完全独立的 Rust-Python 桥接子模块，不影响现有功能
4. 支持 feature flag 开关，可优雅降级到现有规则引擎
5. 轻量级、高性能（推荐延迟 < 50ms）

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **完全独立** | 推荐子模块通过 feature flag 隔离，禁用时零开销 |
| **优雅降级** | Python 环境不可用或进程崩溃时，自动回退到 Rust 规则引擎 |
| **轻量优先** | 优先选择依赖少、体积小的算法库，避免引入重量级框架 |
| **在线学习** | 推荐系统从用户点击/启动行为中持续学习，无需离线训练 |
| **隐私安全** | 所有数据本地处理，不上传任何用户信息 |

## 3. 技术选型

### 3.1 推荐算法选型

#### 3.1.1 核心算法组合

经过全网调研和场景匹配，选用以下**三层推荐算法**：

| 层级 | 算法 | 库 | 用途 | 延迟 |
|------|------|----|------|------|
| L1 内容召回 | TF-IDF + 余弦相似度 | scikit-learn | 基于应用名称/类别/标签的内容相似度 | < 5ms |
| L2 上下文排序 | LinUCB 上下文老虎机 | lightrl | 根据当前上下文动态调整推荐权重 | < 3ms |
| L3 序列模式 | n-gram 序列统计 | 自研 (纯 Python) | 捕捉应用切换序列模式 | < 2ms |

**最终推荐分 = w1 × content_score + w2 × bandit_score + w3 × sequence_score**

#### 3.1.2 为什么不选这些库

| 库 | 排除原因 |
|----|----------|
| **implicit (ALS/BPR)** | 协同过滤需要多用户数据，单用户场景效果有限 |
| **LightFM** | 特征工程复杂，小数据量下收益低于实现成本 |
| **oximedia-recommend (Rust)** | 社区不成熟、下载量仅 325、功能过重 |
| **disco-rust** | 仅支持 CF，不支持 content-based 和 bandit |
| **Vowpal Wabbit** | 体积大（~50MB）、部署复杂，杀鸡用牛刀 |
| **深度学习模型** | 数据量不足、推理慢、依赖重 |

#### 3.1.3 选用库详细评估

**1. scikit-learn (TF-IDF)**
- **优势**：成熟稳定、文档完善、Python 生态标配
- **体积**：~50MB（含 numpy/scipy）
- **适用场景**：应用名称、标签、窗口标题的向量化和相似度计算
- **为什么适合**：几百个应用的 TF-IDF 矩阵计算 < 10ms，余弦相似度查询 < 1ms

**2. lightrl (LinUCB)**
- **优势**：极轻量（~50KB，核心代码 300 行）、零重依赖、仅需 tqdm
- **体积**：< 100KB
- **适用场景**：根据上下文特征（时间、前台应用、窗口类型）动态调整推荐臂的权重
- **为什么适合**：在线学习、实时反馈、exploration/exploitation 平衡，非常适合单用户个性化
- **GitHub**: https://github.com/detrin/lightrl

**3. 自研 n-gram 序列挖掘**
- **优势**：无额外依赖、实现简单、可解释性强
- **适用场景**：捕捉"打开 VS Code 后常打开 Terminal"这类序列模式
- **实现复杂度**：~100 行 Python，使用滑动窗口统计应用切换频率

### 3.2 Rust-Python 桥接选型

#### 3.2.1 方案对比

| 方案 | 耦合度 | 性能 | 隔离性 | 部署难度 | 调试难度 |
|------|--------|------|--------|----------|----------|
| **subprocess + stdio JSON** ⭐ | 极低 | 中 (~5ms IPC) | 最高 | 最简单 | 最简单 |
| pyo3 嵌入式 | 高 | 最高 | 低 | 复杂 | 复杂 |
| 命名管道 (Named Pipe) | 中 | 高 | 中 | 中等 | 中等 |
| HTTP/gRPC | 低 | 低 | 高 | 高 | 中等 |
| 共享内存 | 中 | 最高 | 中 | 高 | 高 |

#### 3.2.2 推荐方案：subprocess + JSON-RPC over stdio

**入选理由**：

1. **完全隔离**：Python 进程崩溃不影响 Rust 主进程，自动重启
2. **部署简单**：系统 Python 即可，无需编译 native 模块
3. **调试友好**：Python 侧可独立运行，stdin/stdout 直接交互
4. **性能足够**：推荐计算 < 10ms + IPC 序列化 < 5ms = 总计 < 20ms
5. **无版本冲突**：不嵌入 Python 解释器，避免 ABI 兼容性问题
6. **feature flag 友好**：禁用时不启动子进程，零运行时开销

**协议设计**：


## 5. 推荐算法详细设计

### 5.1 L1: 内容推荐 (TF-IDF + 余弦相似度)

#### 5.1.1 特征构建

为每个应用构建文本特征向量：

| 字段 | 权重 | 说明 |
|------|------|------|
| 应用名称 | ×3 | 名称是最重要的信号 |
| 应用类别 | ×2 | dev/browser/office 等 |
| 描述/标签 | ×1 | 从名称和路径提取的关键字 |
| 可打开的文件类型 | ×1.5 | .rs/.py/.docx 等 |

```python
# 示例: VS Code 的特征文本
feature_text = """
visual studio code vscode code editor ide
dev development programming
rust python javascript typescript
.rs .py .js .ts .html .css
"""
```

#### 5.1.2 相似度计算

```python
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

# 构建索引 (应用启动时一次性构建)
vectorizer = TfidfVectorizer(token_pattern=r'\b\w+\b', stop_words='english')
tfidf_matrix = vectorizer.fit_transform(all_app_features)

# 查询: 根据当前上下文找相似应用
context_vector = vectorizer.transform([context_text])
similarities = cosine_similarity(context_vector, tfidf_matrix).flatten()
```

#### 5.1.3 上下文文本构建

从多种信号构建查询文本：

```python
context_parts = []

# 1. 前台应用名称
if foreground_app:
    context_parts.append(foreground_app_name * 3)  # 高权重

# 2. 浏览器标签标题
for tab in browser_tabs:
    context_parts.append(tab.title)

# 3. 编辑器打开的文件
for file in open_files:
    context_parts.append(file.name)
    context_parts.append(file.extension * 2)

# 4. 最近使用的应用
for app in recent_apps[:5]:
    context_parts.append(app.name)

context_text = ' '.join(context_parts)
```

### 5.2 L2: 上下文老虎机 (LinUCB)

#### 5.2.1 问题建模

- **臂 (Arm)**：每个推荐候选应用 = 一个臂
- **上下文特征 (Context)**：当前环境的向量化表示
- **奖励 (Reward)**：用户是否点击/启动了推荐的应用（1.0 / 0.0）

#### 5.2.2 特征工程

| 特征类别 | 示例特征 | 维度 |
|----------|----------|------|
| 时间特征 | hour_sin, hour_cos, weekday, is_weekend | 6 |
| 前台应用 | 应用类别 one-hot (12 类) | 12 |
| 上下文类型 | 是否有浏览器标签、是否有编辑器文件 | 4 |
| 应用固有特征 | launch_count (归一化), 类别 embedding | 8 |
| **总计** | | **~30 维** |

#### 5.2.3 算法流程

```python
from lightrl import LinUCBBandit

# 初始化
bandit = LinUCBBandit(n_arms=n_apps, n_features=30, alpha=1.0)

# 推荐时: 选择 UCB 最高的臂
context_features = build_context_features(current_context)
predictions = bandit.predict(context_features)  # 返回每个臂的预估奖励 + UCB
top_arms = np.argsort(predictions)[-20:]  # 取前 20 个

# 用户点击后: 更新模型
bandit.update(chosen_arm_index, context_features, reward=1.0)
```

#### 5.2.4 Exploration vs Exploitation

- `alpha` 参数控制探索程度：alpha 越大 → 探索越多
- 初期 alpha=2.0（多探索），随使用量增加逐渐降到 0.5
- 新应用加入时，给予临时的"探索加成"确保被发现

### 5.3 L3: 序列模式挖掘 (n-gram)

#### 5.3.1 模式发现

统计应用切换序列中的频繁模式：

```python
from collections import defaultdict

# 滑动窗口提取 2-gram 和 3-gram
transition_counts_2 = defaultdict(int)  # (A, B) → count
transition_counts_3 = defaultdict(int)  # (A, B, C) → count

for session in user_sessions:
    # 2-gram
    for i in range(len(session) - 1):
        transition_counts_2[(session[i], session[i+1])] += 1
    # 3-gram
    for i in range(len(session) - 2):
        transition_counts_3[(session[i], session[i+1], session[i+2])] += 1
```

#### 5.3.2 序列推荐分

```python
def sequence_score(current_app, recent_history, candidate_app):
    score = 0.0
    
    # 2-gram: 最近一个应用 → 候选
    last_app = recent_history[-1] if recent_history else None
    if last_app:
        key = (last_app, candidate_app)
        if key in transition_counts_2:
            score += transition_counts_2[key] * 0.6
    
    # 3-gram: 最近两个应用 → 候选
    if len(recent_history) >= 2:
        key = (recent_history[-2], recent_history[-1], candidate_app)
        if key in transition_counts_3:
            score += transition_counts_3[key] * 1.0  # 3-gram 权重更高
    
    return score
```

### 5.4 混合排序 (Hybrid Ranker)

#### 5.4.1 分数融合

```python
def hybrid_rank(candidates, context, weights):
    scores = {}
    
    for app in candidates:
        s_content = content_recommender.score(app, context)
        s_bandit = bandit_recommender.score(app, context)
        s_sequence = sequence_miner.score(app, context)
        
        final_score = (
            weights['content'] * s_content +
            weights['bandit'] * s_bandit +
            weights['sequence'] * s_sequence
        )
        scores[app.id] = final_score
    
    # 按分数排序
    ranked = sorted(candidates, key=lambda a: scores[a.id], reverse=True)
    return ranked
```

#### 5.4.2 多样性控制 (MMR - Maximal Marginal Relevance)

避免推荐结果同质化：

```python
def mmr_rerank(candidates, scores, similarity_matrix, lambda_param=0.7, top_n=20):
    """
    Maximal Marginal Relevance 重排序
    lambda=1.0 → 纯相关性排序
    lambda=0.0 → 纯多样性排序
    """
    selected = []
    candidate_set = set(c.id for c in candidates)
    
    for _ in range(min(top_n, len(candidates))):
        best_score = -float('inf')
        best_id = None
        
        for cid in candidate_set:
            # 相关性分
            relevance = scores[cid]
            
            # 与已选项的最大相似度
            max_sim = 0
            for sid in selected:
                sim = similarity_matrix[cid][sid]
                max_sim = max(max_sim, sim)
            
            # MMR 分数
            mmr = lambda_param * relevance - (1 - lambda_param) * max_sim
            
            if mmr > best_score:
                best_score = mmr
                best_id = cid
        
        if best_id is None:
            break
        
        selected.append(best_id)
        candidate_set.remove(best_id)
    
    return selected
```

```rust
        &self,

    ) -> Result<RecommendResult, Error> {

            method: "feedback".into(),
            params: json!(feedback),
        };
        
        // 异步发送，不阻塞
        tokio::spawn(async move {
            let _ = self.send_request(request).await;
        });
    }
```

### 7.4 Python 侧实现

```python
# server.py
import sys
import json

class JsonRpcServer:
    def __init__(self):
        self.handlers = {}
        self.content_recommender = None
        self.bandit_recommender = None
        self.sequence_miner = None
    
    def register(self, method, handler):
        self.handlers[method] = handler
    
    def run(self):
        for line in sys.stdin:
            try:
                request = json.loads(line.strip())
                response = self.handle_request(request)
                sys.stdout.write(json.dumps(response) + '\n')
                sys.stdout.flush()
            except Exception as e:
                error_response = {
                    "jsonrpc": "2.0",
                    "id": request.get("id"),
                    "error": {"code": -32603, "message": str(e)}
                }
                sys.stdout.write(json.dumps(error_response) + '\n')
                sys.stdout.flush()
    
    def handle_request(self, request):
        method = request.get("method")
        params = request.get("params", {})
        handler = self.handlers.get(method)
        
        if handler is None:
            return {
                "jsonrpc": "2.0",
                "id": request["id"],
                "error": {"code": -32601, "message": "Method not found"}
            }
        
        result = handler(params)
        return {
            "jsonrpc": "2.0",
            "id": request["id"],
            "result": result
        }

def main():
    server = JsonRpcServer()
    
    # 注册处理器
    server.register("initialize", handle_initialize)
    server.register("recommend", handle_recommend)
    server.register("feedback", handle_feedback)
    server.register("update_candidates", handle_update_candidates)
    server.register("health_check", lambda p: {"status": "ok"})
    
    server.run()

if __name__ == "__main__":
    main()
```
