对现有项目实施系统性架构重构工程，以解决当前存在的架构复杂度高、功能模块缺失与耦合度过高并存、硬编码现象普遍等核心问题。

必要时使用以下mcp工具完成辅助设计和开发工作：
1. Fetch MCP 搜索相关技术、设计
2. context7 MCP 了解最新的技术文档和开发方式
3. sequential-thinking MCP 采用顺序思考方式，确保设计和实现的逻辑清晰、有序
4. supermemory MCP 记忆和检索项目相关知识，避免重复工作和错误
5. Magic MCP 用于搜索UI设计、组件设计等美观、简约的设计方案

本次重构工作需达成以下具体技术目标：

1. 代码优化与精简：
   - 执行系统性代码审计，识别并移除冗余代码、重复业务逻辑及未使用功能模块
   - 重构代码结构以提升可读性与可维护性，遵循行业最佳实践与编码规范
   - 实现配置与参数的集中化管理，将所有硬编码内容按功能模块提取至独立配置文件

2. 模块化设计与实现：
   - 基于功能职责进行系统模块划分，确保每个模块具备明确的边界定义与单一职责
   - 严格禁止模块间直接交互或调用内部实现细节
   - 强制采用标准化通信机制：明确定义的API接口、服务注册模式、功能扩展点及依赖注入等

3. 项目目录结构重组：
   - 根据模块化设计原则重新规划项目目录体系
   - 确保每个模块拥有独立的目录空间，包含其相关的所有源代码、配置文件及资源文件
   - 建立清晰的模块间依赖关系映射

4. 模块独立性保障机制：
   - 实现模块间的高度解耦，确保任何模块的移除或禁用不会导致系统核心功能崩溃，仅表现为对应功能的缺失
   - 构建系统降级运行能力，在缺少特定模块时仍能正常启动并运行其他可用功能
   - 明确区分核心模块与扩展模块：
     * 核心层模块包括：后端服务框架模块、服务模块、命令模块、搜索引擎模块、消息管理模块、文件管理模块、文件图标提取模块等
     * 前端核心模块包括：前端APP框架模块、搜索栏模块、工作区模块（包含现有搜索结果面板，工作区模块需进一步按照groupsection设计划分子模块）、状态栏模块等
     * UI通用业务模块包括：软件图标获取模块（优先从后端获取图标）、消息展现模块、快捷键管理模块等

5. 扩展性架构设计：
   - 为各模块设计并实现标准化扩展接口
   - 支持通过注册机制动态添加新功能或替换现有模块实现
   - 确保扩展功能的实现无需修改核心系统代码

重构实施要求：
1. 制定详细的模块划分方案文档，明确各模块的职责范围、API定义及交互协议
2. 编写完整的架构设计文档，包括模块关系图、数据流图及接口定义规范
3. 实施全面的测试策略，包括单元测试、集成测试、模块独立性测试及系统稳定性测试
4. 将上述设计思路完整更新至CLAUDE.md文档，作为项目首要设计指导文件
5. 所有编码设计工作必须严格遵循本重构方案执行

交付成果：重构后的源代码、模块划分方案文档、架构设计文档、测试报告（报告全部输出到docs目录下）及更新后的CLAUDE.md设计指导文档、更新README.md文档。
